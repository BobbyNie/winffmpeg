# Windows 视频转换与合并设计

## 目标

- 在 Windows 使用 Python 3.11+、FFmpeg 和 FFprobe。
- 默认读取 `video`。每个第一层子目录是一组，递归查找视频。
- 按不区分大小写的文件名进行字典序升序排序。clip10 排在 clip2 前面。
- 不同子目录的同名文件按相对路径字典序排序。
- 每组输出 `video/output/<第一层子目录名>.mp4`。
- 默认输出 H.264、AAC、yuv420p、25 帧/秒逐行视频。支持整数与分数帧率。
- 默认强制使用 bwdif 去隔行。支持自动模式、关闭模式与手动场序。

## 方案选择

纯批处理的路径和错误处理难以维护。PowerShell 涉及执行策略和版本差异。
使用 Python 标准库实现逻辑，提供 .cmd 启动器。不依赖第三方 Python 包。

## 数据流

1. 检查参数、工具与输入目录。
2. 枚举分组与片段，排除 output 和符号链接。
3. 通过 FFprobe 读取视频与音频信息。
4. 以首段视频的显示尺寸为目标，统一偶数尺寸，保持比例并补黑边。
5. 每段执行去隔行、帧率转换、H.264 编码与音频标准化。
6. 中间文件使用 NUT、H.264 和无损 PCM 音频，避免逐段 AAC 编码延迟。
7. 使用 concat demuxer 合并中间文件，复制视频，最终仅编码一次 AAC。
8. 在输出目录创建临时文件，成功后替换目标文件。失败时保留原输出。

## 音频与数据安全

默认使用第一条音轨，支持选择其他音轨。无音轨的片段补静音。
音频统一为 48 kHz 双声道，过短补静音，过长按视频终点截断。
不修改源视频。默认拒绝覆盖已有输出，必须显式传入 --overwrite。
忽略不支持的文件扩展名。支持扩展名的损坏文件必须报错，不能静默跳过。
失败组不阻止其他组处理，但进程最终返回非零退出码。
不上传本地素材。GitHub Actions 使用自动生成的视频。

## TDD 与验收

逐项执行：失败测试、最小实现、通过测试、提交 Git。
验证递归分组、文件名字典序排序、output 排除、25P、可调帧率、异构片段、音频、
中文与特殊路径、错误码、覆盖保护、源文件不变和真实去隔行效果。
去隔行验收需检查输出像素的运动梳齿减少，不能仅检查 progressive 标签。
Windows 与 Linux CI 运行相同的标准库 unittest 测试；Windows 另验收 .cmd 启动器。
